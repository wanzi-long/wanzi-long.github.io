voice-sync-video · 音画同步视频生产管线

把"一段文案 + 一个产品"变成"配音和动画严格同步的成片"——场景边界 = TTS 句级时间戳，物理上杜绝音画跑偏。
作者：唐浩翔形态：Agent 技能（SKILL.md） Remotion / HyperFrames · TTS · 句级时间戳6 个人工硬闸门

1. 核心机制：时间戳是地基

TTS 合成时开启「字幕/时间戳」选项
  → 官方句级 time_begin / time_end（如 MiniMax subtitle_enable=true）
  → 换算帧号写入 timing.ts（唯一事实来源）
  → 场景边界 = 句边界，字幕条读同一份时间戳
降级链：配音无时间戳 → ASR 回识别取句级时间戳 → 仍不行才按字数比例估算并明确标注"降级"

传统做法是按字数/感觉估算对齐，本管线把对齐建立在 TTS 官方时间戳上，音画同步从"调出来的"变成"结构保证的"。

2. 五条铁律

  1. 闸门必停：标记 🔴 的环节必须停下来等用户拍板，禁止自作主张直出
  2. 时间戳是硬约束：禁止按字数/感觉估算对齐
  3. 收费 TTS 先探针：按量计费的 TTS 先发 1 条最短探针并报价格，用户点头才批量（源自一次 10 分钟欠费 ¥21.5 的真实事故）
  4. 静帧 QA 必做：全片渲染前必须出关键帧静图过目——印章压字、元素错位都是静帧抓出来的
  5. 配音变 → 节奏重排：换音色/改稿后必须重取时间戳并重排每个场景的内部动画

3. 流程总览：13 步 · 6 个硬闸门

设计哲学：AI 不一股脑直出。6 个硬闸门把"叙事方向、口播稿、配音、美术风格、静帧、终审"的决策权留给人类，自动化只负责执行层。

4. 组件资产复用（motion-material-hub 对接）

  • 23 个零依赖确定性组件：帧驱动、任意帧可 seek、无 gsap/motion 依赖，复制进工程即用——时间参数全部帧数，对时间戳天然友好
  • 六环调用法：G 环节选款 → I 环节装配调参 → J 环节静帧 QA，形成闭环
  • 审美评分细则（taste-rubric）：选款排序与静帧自评共用同一把尺，<7 分自动返修
  • 新组件回收入库：项目中新写的组件按 porting-sop 沉淀回组件仓，资产越用越厚
